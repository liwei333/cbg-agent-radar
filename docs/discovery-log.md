# Discovery Log — 藏宝阁角色搜索第一轮

## D-001 列表顺序在每次重新加载后不稳定

现象：
每次 goto 搜索结果页后，角色的排列顺序会发生变化。同一个 index 在两次加载后可能对应不同角色。

解决：
进入详情前应通过角色名+价格确认目标，而不是依赖固定 index。

是否值得程序化：
是。程序化时应使用 itemId 或角色名作为唯一标识，而非列表 index。

## D-002 角色卡片没有直接 href 链接

现象：
列表页的角色卡片（`.list-item.product-item.js_product_item`）没有 `<a href>` 链接，也没有 onclick 属性。通过 JS click() 触发跳转。

解决：
使用 `page.evaluate()` 执行 `cards[index].click()` 触发导航，然后等待 URL 变化。

是否值得程序化：
是。已验证稳定可重复。

## D-003 详情页数据字段丰富但需展开

现象：
详情页默认显示：成就、总修、总宠修、经验、机缘、潜能果、乾元丹数量、道具数、召唤兽数、限量锦衣数。
但装备具体属性、召唤兽具体技能、生活技能详情需要展开或进一步操作。

解决：
本轮只记录概览数据，装备和宝宝详情留待后续轮次。

是否值得程序化：
是。概览数据已通过 DOM 提取稳定。

## D-004 筛选条件通过 URL 参数传递

现象：
价格筛选通过后，URL 变为 `price_min=350000&price_max=650000`（单位：分）。
直接 goto 带参数的 URL 可以恢复筛选状态。

解决：
构造带参数的 URL 直接访问筛选结果页。

是否值得程序化：
是。URL 参数化是稳定的筛选方式。

## D-005 账号显示"购买及出售功能受限"

现象：
登录账号（collector-account-01）显示"购买及出售功能受限"，但不影响浏览和搜索。

解决：
本轮只做浏览搜索，不触发购买流程，无需处理。

是否值得程序化：
否。仅作记录。

## D-006 搜索入口为热门标签点击

现象：
搜索页（/cgi/mweb/search）有热门搜索标签"等级109的角色"，点击后跳转到搜索结果页。
也可以直接构造搜索结果页 URL。

解决：
直接 goto 带 keyword 和筛选参数的搜索结果页 URL。

是否值得程序化：
是。URL 模板已确认稳定。

## D-007 列表页 DOM 可提取基础信息但不含详情

现象：
列表页可提取：门派、等级、成就、总修、总宠修、服务器、价格、标签（锦衣/祥瑞等）。
无法提取：装备属性、召唤兽技能、生活技能详情。

解决：
列表页只记录基础信息，详情通过点击进入详情页获取。

是否值得程序化：
是。已验证 `.pi-main`、`.price`、`.pi-info` 选择器稳定。

## D-008 移动端装备详情需要点击图标触发弹窗

现象：
详情页装备区域默认只显示图标，不显示文本属性。
点击装备图标后，页面底部弹出装备详情（名称、等级、属性、宝石、特效等）。

解决：
通过 JS click() 触发装备图标点击，等待弹窗出现后提取 `.equip_desc_yellow` 内容。

是否值得程序化：
是。已验证 4256777 和 8623359 的装备详情弹窗。

## D-009 移动端召唤兽详情需要切换到"召唤兽/孩子"tab

现象：
默认"角色总览"tab不显示召唤兽详情。
需要点击"召唤兽/孩子"tab，然后点击召唤兽图标查看每只宝宝的技能、资质、成长等。

解决：
1. 点击"召唤兽/孩子"tab
2. 点击召唤兽图片
3. 提取技能列表和资质数据

是否值得程序化：
是。已验证 4256777（画魂）、8623359（鼠先锋等4只）、5927781（泪妖）的召唤兽详情。

## D-010 锦衣"查看全部"可展开完整列表

现象：
默认只显示前3件限量锦衣名称。
点击"查看全部"后显示完整锦衣列表（限量+普通+特效+头像框等）。

解决：
点击"查看全部"按钮后提取完整锦衣数据。

是否值得程序化：
是。已验证 4256777（26件）、8623359（17件）、5927781（16件）的锦衣列表。

## D-011 卖家拆售物品的装备不在角色详情页展示

现象：
5927781 是"卖家拆售物品"，装备和召唤兽被单独拆出来卖。
角色详情页不显示装备图标，只显示"拆售道具"摘要（永不磨损、锻炼等级等）。

解决：
对于拆售物品，记录 `isSplitSale: true`，并记录拆售区域的摘要信息。
具体装备详情需要单独查看拆售商品页面。

是否值得程序化：
是。需要识别"卖家拆售物品"标记。

## D-012 PC版URL (xyq.cbg.163.com) 对移动端商品返回404

现象：
移动端商品URL (xyq-m.cbg.163.com) 在PC版 (xyq.cbg.163.com) 返回404。
装备和召唤兽详情只能在移动端页面查看。

解决：
所有详情采集必须在移动端页面 (xyq-m.cbg.163.com) 进行。

是否值得程序化：
是。已确认URL模板。
